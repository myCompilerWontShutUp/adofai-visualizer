# ADOFAI Practice Visualizer

ADOFAI(얼불춤) 커스텀 맵을 읽어 **Falling Note**로 보여주는 개인용 Windows 연습 도구입니다. 기본 최대 타일 수는 4이며, 최대 키 패턴에 속한 타일만 번호 오름차순으로 표시합니다. 기본 화면은 3·4·5·6 네 레인입니다.

현재는 읽기 전용 맵 동기화, 캐시 기반 곡 불러오기, setting, 동적 1/2/4/8키 노트 생성, OFF/WAITING/PLAYING, 전역 키 관찰, 절대 시간 기반 렌더러가 있습니다. Plum - R, RUSH E, HeHeHe, Machinegun Psystyle의 사용자 제공 맵으로 파싱·노트 생성·체크포인트 준비를 확인했습니다. version 4/8/13/15/18의 검증된 이벤트 조합, 구형 pathData, 음수 각도와 Pause를 지원합니다. 합성 규칙 미리보기도 유지합니다. 모든 ADOFAI 이벤트를 지원하는 것은 아니며 음악은 재생하지 않습니다. 게임 조작·DLL Injection·메모리 수정·자동 입력은 사용하지 않습니다.

게임 파일에서 확인한 규칙에 따른 독립 계산과 전체 8,113개 노트를 대조했으며 최대 차이는 약 0.012ms입니다. 실제 화면·오디오 동기화 측정과는 구분합니다. [타이밍 대조 결과](docs/timing-comparison.md).

## 기술 선택

C# / .NET 9 / WPF를 사용합니다. 설치된 SDK 9.0.305와 Windows Desktop 참조 팩으로 빌드를 확인하기 위한 선택입니다. 본격 개발 시 지원 정책을 확인하고 대상 .NET 버전 업그레이드를 검토합니다. WPF UI와 맵·타이밍 로직은 별도 프로젝트로 분리했습니다.

## 다른 PC에서 최신 버전 받기

이 폴더는 git 저장소입니다. 다른 컴퓨터에서는 저장소를 받아 빌드하면 그대로 최신 버전입니다.

```powershell
git clone <저장소 주소> visualizer
cd visualizer
.\build.ps1 -Configuration Release
```

필요한 것은 **.NET SDK 9.0.305**(`global.json`이 고정) 하나뿐입니다. NuGet 소스를 비워 두어 패키지 복원이 없습니다.

### 받기 (`update`)

**올리는 것은 VS Code 등 편집기의 git으로** 하고, 다른 PC는 **받기만** 합니다.

```powershell
.\update.ps1 -Check                 # 최신인지 보기만 함
.\update.ps1                        # 받고 Release 빌드까지
```

앱에서는 콘솔(Ctrl+T)에 `update`를 칩니다. 최신이면 그렇다고 하고 끝나며, 새 버전이 있을 때만 "이 버전으로 갱신합니다. 앱을 닫았다가 다시 엽니다"를 [Y/n]으로 묻습니다. 예라고 하면 **앱이 닫히고 새 버전을 빌드한 뒤 다시 열립니다**(실행 중에는 자기 실행 파일을 덮어쓸 수 없기 때문입니다). 게임에 링커가 설치되어 있으면 함께 갱신합니다. 이 복사본에 직접 고친 내용이 있으면 덮어쓰지 않고 거절하며, `update -force`가 그 내용을 버리고 진행합니다. 특정 버전으로는 `update -force -version:1.0.0`으로 갑니다(위험은 사용자 책임, 항상 [Y/n]). 갱신 뒤 처음 열면 무엇이 바뀌었는지 먼저 보여 줍니다.

**버전 번호**: 1.0.0부터 업데이트마다 마지막 숫자(1.0.1), 큰 변경은 가운데 숫자(1.1.0)를 올립니다. 버전은 `Directory.Build.props`의 `<Version>`을 바꾼 커밋으로 찾으므로 태그가 필요 없습니다. 새 버전을 올리기 전에 그 버전의 소식(`ReleaseNotes.<버전>`)을 언어 파일 두 개에 적어야 테스트가 통과합니다.

**무결성 검사**: 콘솔의 `scannow`가 앱·저장소 파일·링커·맵 사본·수정본·데이터를 검사해 결과만 보여 주고, 고칠 것은 `install -reinstall maps, linker`처럼 권합니다.

**올라가지 않는 것**: 앱 저장소(**스팀 워크숍 맵 사본·설정·메모**)는 저장소 밖 `%LOCALAPPDATA%\AdofaiVisualizer\`에 있어 올라가지 않습니다(1.0.0부터. 그 전에는 저장소 안 `.local/app-data`였고, 1.0.0을 처음 켜면 한 번 그리로 옮깁니다 — 이전 폴더는 그대로 둡니다). 같은 PC의 **모든 복사본이 이 한 곳을 함께 씁니다**. 남의 창작물과 이 PC의 설정이 함께 올라가지 않으므로, 새 PC에서는 맵을 한 번 동기화해야 하고 설정도 그 PC의 것을 씁니다(설정까지 함께 쓰려면 고급 설정의 **데이터 저장 폴더**를 동기화 폴더로 지정합니다). 빌드 산출물(`bin`·`obj`)과 `.local/`도 `.gitignore`가 뺍니다.

원격은 처음 한 번만 만들어 둡니다(비공개 권장).

```powershell
gh repo create <이름> --private --source=. --remote=origin --push
```

## 빌드 및 실행

시연용 Release 빌드를 준비한 상태에서는 루트의 `Launch-Demo.cmd`를 더블클릭하세요. [시연 가이드](docs/demo-guide.md)에 권장 설정, 진행 순서와 현재 지원 범위를 정리했습니다.

Windows와 .NET SDK 9.0.305 호환 패치 및 Windows Desktop 참조 팩이 필요합니다. Visual Studio에서는 .NET 데스크톱 개발 구성으로 솔루션을 열 수 있습니다.

프로젝트 루트에서 PowerShell로 실행합니다.

```powershell
.\build.ps1
# 릴리스 빌드
.\build.ps1 -Configuration Release
# 회귀 테스트 및 화면 렌더링 검증
.\build.ps1 -Test
# PowerShell 실행 정책으로 차단되는 경우 (이번 프로세스에만 적용)
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

스크립트는 도구 홈·NuGet 캐시·임시 경로를 프로젝트 내부 `.local/`로 지정하고 종료 시 프로세스 환경을 복원합니다. 외부 패키지 소스는 비활성화되어 있으며 참조 팩이 없다면 자동 다운로드 대신 빌드가 실패합니다. 이번 작업의 파일 경계 규칙을 지키려면 빌드는 이 스크립트를 사용하세요. IDE의 자동 복원/빌드는 이 환경 설정을 자동으로 사용하지 않습니다.

빌드 후 `src/Visualizer.App/bin/Debug/net9.0-windows/Visualizer.App.exe`를 실행합니다. 앱은 시작 시 Workshop을 읽거나 데이터를 저장하지 않습니다. 테스트는 외부 패키지가 없는 실행형 하네스이며 `build.ps1 -Test`가 빌드 후 실행합니다. 테스트 자료와 캡처는 `.local/test-artifacts/`에만 생성합니다.

## 사용 방법

**레인 키**는 기본 `A S D F J K L ;`(타일 1~8)입니다. 누르면 해당 레인에 옅은 그라데이션이 켜지고, 재생 중이면 누른 것으로 예상되는 노트가 어두워집니다. 누르지 않고 지나간 노트는 그 레인에 빨간 그라데이션으로 잠깐 표시됩니다. 노트는 **판정선**(하단 제거선 위 72px)을 지나 계속 내려가다 맨 아래에서 사라집니다. 레인 키·판정선 높이·입력 인정 범위는 `setting`에서 바꿀 수 있습니다. 시각 피드백일 뿐 게임 판정이 아닙니다. [레인 키 입력 효과](docs/note-rules.md).

체크포인트 줄 오른쪽의 **자동**을 끄면 재생 중 체크포인트가 자동으로 넘어가지 않습니다. 그 옆 **구간** 칸에 타일 번호(예: 20)를 넣고 Enter를 누르면 게임 연습 모드처럼 그 타일부터 준비합니다. 칸을 비우면 체크포인트 기준으로 돌아갑니다. 처음 쓸 때는 맵 동기화가 한 번 필요합니다. [구간 시작](docs/checkpoints.md).

기본 테마는 얼불춤풍 **우주** 테마입니다. `setting` 창 오른쪽 위에서 곡처럼 ◀ 목록 ▶으로 **우주·다크·화이트** 테마를 고를 수 있으며, 설정 창에서 바로 미리보고 **적용**하면 메인 창에도 반영됩니다. 테마는 `src/Visualizer.App/Themes/Palettes/`, 언어는 `src/Visualizer.Core/Localization/Languages/`의 파일로 관리하므로 파일을 추가하고 빌드하면 늘릴 수 있습니다. 초기 설정값은 `src/Visualizer.Core/Settings/DefaultSettings.json`에서 직접 확인·수정할 수 있으며 다시 빌드하면 반영됩니다. 현재 앱 버전(0.0.5)은 메인 화면 오른쪽 아래에 표시됩니다.

**↑ / ↓**로 다음·이전 체크포인트를 선택해 정지 배치할 수 있고 목록 끝에서는 반대쪽 끝으로 넘어갑니다(좌우 방향키는 게임 판정 변경과 겹쳐 쓰지 않음). 전경 필터는 Reset/Start와 같습니다. 두 번째 이후 **체크포인트**나 **구간** 칸의 타일 번호에서 시작하면 노트 배치는 처음부터 재생할 때와 같고, 첫 노트 레인의 키로 시작합니다. 노트 이동 시간은 기본 **720ms**, 체크포인트 자동 적용은 해당 타일의 **판정선 도달 후 1000ms**입니다. `setting`의 **체크포인트 도달 후 대기**에서 조정합니다. [체크포인트 규칙](docs/checkpoints.md).

일반판의 시작·환경 차이에 대응하도록 **시작 대기 시간(기본 0ms)**, **연습 배속(기본 100%)**, **일시정지/이어하기**를 제공합니다. 게임의 첫 타격에 시작하면 대기는 0ms로 두세요. 연습 배속은 게임과 수동으로 맞추며, 로딩·게임 일시정지를 자동 감지하지 않습니다. 형식 버전·원문 카운트다운 안내는 맵 동기화 후 상태 상세에서 확인합니다. 조사 출처와 지원 한계는 [일반판 환경 대응](docs/environment-compatibility.md)에 정리했습니다. DLC는 제외합니다.

**setting → 동타 판정 간격 (ms, 이하)**의 기본값은 10입니다. 묶음의 첫 노트에서 설정 간격 이내인 두 노트를 같은 시각에 표시합니다. 2키 단타+동타는 연속 3레인, 4키 동타는 양 끝의 인접 쌍으로 배치합니다. 동타는 2동타만 표시합니다. 3노트 묶음은 2동타와 가장 늦은 단타 하나, 4노트 묶음은 2동타 두 개로 나눕니다. 레인이 부족하면(예: 최대 4키에서 5노트 묶음) 이유를 표시하고 준비를 중단합니다. 0ms는 정확히 같은 시각만 묶습니다. 설정 적용은 캐시에서 재계산하므로 Map Sync를 다시 할 필요가 없습니다. [동타 규칙과 예외처리](docs/note-rules.md).

한국어가 기본이며 **setting → language → 한국어 / English**로 설정 화면 언어를 바꿀 수 있습니다. 변경 중인 입력값을 유지하며, 적용 시 메인 화면의 주요 표기도 변경합니다. 언어 변경만으로 노트를 재생성하거나 재설정하지 않습니다. 일부 기술 경고는 아직 한국어로 표시합니다.

곡 이름 아래에 **설명서 · 규칙 미리보기 · 예제 (Plum - R)** 묶음이 있고 X로 숨길 수 있습니다(setting → 일반에서 다시 표시). 그 아래 **곡 제목(입력하면 검색) · 동기화 · 불러오기** 줄은 항상 보이며, 맵 폴더는 setting → 일반에서 정합니다. 처음 켜기 전에는 상태 옆에 "F8을 눌러 활성화"가 보입니다. 설명서는 조작 키와 기능을 정리한 창이고, 예제는 `.example`을 읽기 전용으로 읽어 곡 목록에 넣지 않고 바로 준비합니다. 게임에서 Esc로 일시정지하면 노트도 멈추고, 재개 후 다음 타일 키를 누르면 그 레인 노트에 맞춰 이어갑니다. setting → 고급 설정에서 타일 선호도(패턴 타일이 도는 순서)를 정하고 설정을 JSON으로 내보내거나 가져올 수 있습니다. **시작** 버튼을 누르면 원문에서 계산한 726개 hit의 노트를 표시합니다. 첫 hit 기준 마지막 hit는 약 138.667초입니다. 체크포인트 6개를 선택하여 해당 구간부터 준비할 수 있습니다. J/Enter로 시험하려면 아래 **⚙ → setting**에서 ADOFAI 활성 창 제한을 끄거나 게임이 활성 창인 상태에서 사용하세요. 오디오는 재생하지 않습니다.

1. **Map Sync**: 상단 디렉터리 입력에 Workshop 또는 Custom Level 폴더를 지정하고 수동 실행합니다. 하위 `.adofai`를 읽고 프로그램 캐시를 갱신합니다. 실시간 감시는 없습니다. 기존 라이브러리에 다른 루트도 추가할 수 있습니다.
2. **곡 불러오기 / Load Song**: 콤보박스에서 이미 동기화된 곡을 선택해 캐시를 불러옵니다. 원본을 다시 읽지 않습니다. 지원 범위에 있는 실제 맵은 타임라인을 생성하며, 미지원 이벤트는 Unsupported와 이유를 표시합니다. 이전 버전에서 Unsupported로 저장한 맵은 다시 동기화하세요.
3. **F8 / ON·OFF**: Visualizer를 켜거나 끕니다. 시작 상태는 OFF이며, 켜면 준비 상태로 이동합니다. 끄면 진행이 중단되고, 다시 켜도 자동 재생하지 않습니다.
4. **규칙 미리보기**: 실제 곡과 별개의 합성 타임라인을 불러오고 Visualizer를 켜 WAITING으로 배치합니다. 합성 체크포인트 1~3을 시험할 수 있습니다.
5. **setting**: 언어, 조작 키, 활성 창 제한, 최대 타일 수, 동적 타일 수, 경계값(ms), 이동 시간(ms), 두께 배율, 표시 보정, 패턴 및 시작 타일을 수정합니다. setting 단축키의 기본값은 미지정입니다. 패턴 설정 변경은 캐시에서 재생성 후 재설정하며, 시각·언어 설정 변경은 재생 시계와 노트 목록을 유지합니다. 설정은 메모리에서만 유지됩니다.
6. **Enter / Reset**: 현재 체크포인트 기준 첫 hit event를 t=0으로 정규화합니다. 기본 offset=0에서 첫 노트는 판정선, 이후 노트는 상대 hit time에 맞는 위치에 정지합니다.
7. **J / Start**: 배치를 바꾸지 않고 elapsed 시계만 시작합니다. 재생 중 중복 Start는 무시합니다. 기본적으로 어느 앱이 전경이든 Reset/Start 키에 반응합니다(앱 0.0.3부터). 게임이나 이 비주얼라이저가 활성일 때만 반응하게 하려면 setting → 고급 설정의 전역 입력 범위를 켜세요.
8. **체크포인트**: 목록에서 선택하면 즉시 해당 구간을 정지 배치합니다. 시작/J로 재생하고 재설정/Enter로 다시 준비합니다. 진행 중 번호 갱신은 Visualizer 시간 기준이며 게임의 사망/재시작을 자동 감지하지 않습니다. [근거 및 사용법](docs/checkpoints.md).

기본 창은 480×800이며, 맵 선택과 상태 상세를 접어 노트 영역을 길게 사용할 수 있습니다. 설정은 아래쪽 **⚙** 버튼으로 별도 창을 엽니다. 최대 4키이면 네 레인만 표시하며 논리 타일 번호는 기본값 3·4·5·6을 유지합니다. 이전 맵 캐시는 **맵 동기화**를 다시 실행해야 체크포인트가 추가됩니다.

전역 입력은 Raw Input 관찰 방식이며 키를 차단하거나 자동 입력하지 않습니다. 기본 프로세스 이름은 `A Dance of Fire and Ice`이며 Settings에서 실행 환경에 맞게 수정할 수 있습니다. 전경을 확인하지 못하면 Reset/Start를 무시합니다. 전역 토글은 전경 제한 없이 동작하며 설정 창/입력 편집 중에는 단축키 실행을 잠시 막습니다. 자세한 범위는 [전역 입력 문서](docs/windows-input.md)를 참고하세요.

기본 경계값은 `<20ms: 8K`, `<50ms: 4K`, `<500ms: 2K`, `>=500ms: 1K`이며 최대 타일 수로 제한합니다. 패턴 중간에는 모드를 바꾸지 않습니다. 상세 규칙과 명세 해석은 [노트 규칙 문서](docs/note-rules.md)에 기록했습니다.
