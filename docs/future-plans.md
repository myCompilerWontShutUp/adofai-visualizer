# 앞으로의 설계 답변 (2026-09-18)

사용자 질문 세 가지에 대한 답변 기록입니다. **아직 구현하지 않았고, 구현 지시는 따로 받습니다.**

> 시작 동기화는 2026-09-28 사용자 승인으로 진행 중입니다. 설계·근거·단계는 `docs/game-sync-plan.md`가 원본입니다.

## 1. ADOFAI 모드로 비주얼라이저와 교류

**기술적으로 가능하지만 "리소스팩"으로는 불가능하고 코드 모드여야 합니다**(리소스팩에는 스크립트 실행 경로가 없음). ADOFAI는 Unity + Mono라 UnityModManager/BepInEx 계열 모드가 널리 쓰이고 맵 형식에도 `requiredMods` 필드가 있습니다.

모드가 게임 쪽에서 밀어 줄 수 있는 것(모두 ReflectionOnly로 확인한 필드):

- **곡 동기화·자동 불러오기** — 재생 중 레벨의 경로·원문 해시 → 캐시에서 자동 로드. 가장 확실하고 쉬운 이득.
- **사망·재시작·일시정지** — 지금은 자동 감지하지 않는 것이 원칙인데, 이벤트를 받으면 추정이 아닌 사실로 처리 가능.
- **첫 판정선(동기화)** — `scrConductor`의 곡 위치나 첫 hit 시각을 받아 J 수동 시작과 표시 보정을 대체. 가장 큰 개선.
- 체크포인트 번호, 연습 모드 시작 타일, 배속도 같은 경로로 수신 가능.

전송은 로컬 IPC(명명 파이프 / localhost 소켓)로 이벤트만 보내고, 비주얼라이저는 자체 시계를 유지한 채 주기적으로 드리프트만 보정하는 구조가 안전합니다.

**전제 조건과 위험**

- 안전 규칙 6("게임 자체를 조작하는 기능 금지")의 경계를 다시 정해야 합니다. 게임 안에서 도는 코드를 배포하는 것이므로 "상태를 읽어 내보내기만 하고 게임 로직·메모리·입력은 건드리지 않는 모드"로 **범위를 새로 승인**받아야 작업할 수 있습니다.
- 게임 폴더에 파일을 넣는 설치 단계가 생깁니다(현재는 게임·맵 폴더 쓰기 금지). 별도 승인 항목입니다.
- 게임 업데이트마다 깨질 수 있습니다. 필드·메서드가 바뀌면 버전별 분기가 늘어납니다.
- 모드 사용이 리더보드·업적에 주는 영향은 확인한 바 없습니다. 공개 기록을 낼 계획이면 먼저 확인이 필요합니다.
- 모드가 없는 환경에서도 지금처럼 동작해야 하므로 **모드는 선택적 보조 경로**로 두고 기존 수동 흐름을 유지합니다.

## 2. 노트 직접 수정(에디트) 기능

**구현 가능하고 현재 구조와도 맞습니다.** 지켜야 할 경계:

- **수정 대상은 "준비된 노트"(레인 배치·동타 묶음)이지 타임라인이 아닙니다.** 원본·캐시 hit 시각은 계속 불변이고, 에디트는 그 위에 덮는 오버레이로 저장합니다.
- **저장 키는 노트 번호가 아니라 원본 hit 번호**여야 합니다. 설정이 바뀌면 노트 목록은 재생성되지만 hit 번호는 고정이라 수정이 살아남습니다.
- **레인 변경**: 쉽습니다. 해당 hit의 타일을 강제하고 기존 검증(같은 시각 중복 레인 금지, 롱노트가 잡은 레인 금지, 보이는 타일만 사용)을 통과시키면 되며, 실패는 현재 배치 실패와 같은 방식으로 이유를 표시합니다.
- **분해**는 표시 플래그(`StartsChord`)만 끄면 되므로 간단합니다.
- **병합**은 서로 다른 시각의 hit를 하나로 보이게 하려면 표시 시각을 앞 노트로 당겨야 합니다. 원본은 그대로이므로 규칙 위반은 아니지만 "표시 시각 = 묶음 첫 노트"를 사용자 지정 묶음에도 적용한다고 명문화하고, 허용 간격 상한을 두어야 합니다.
- **불러올 때 질문**(커스텀 배치 / 설정 규칙)은 기존 확인 창 구조로 처리 가능합니다. 추가로 필요한 것은 **무효가 된 수정의 처리 규칙**입니다(예: 최대 4키로 줄였는데 6번 레인 지정이 남은 경우 → 그 항목만 버리고 알릴지, 전체를 무시할지).
- **맵이 바뀌면**(원문 해시 변경) 수정이 다른 노트에 붙을 수 있으므로 해시를 함께 저장해 경고하거나 무효화합니다.
- 저장 위치는 곡 리스트와 같은 앱 전용 저장소이고 **설정 JSON 내보내기에서는 제외**합니다.
- 규모가 크므로 **① 레인 변경 → ② 분해/병합 → ③ 불러오기 질문** 순으로 나눠 만듭니다.

## 3. 인스톨러 vs 첫 실행 파일 생성

**배타적이지 않습니다. 지금은 "첫 실행 때 생성"이 필수이고 인스톨러는 나중에 선택입니다.**

- 데이터는 어차피 `%LOCALAPPDATA%\Visualizer\` 같은 사용자 폴더에 있어야 합니다. `Program Files` 아래는 관리자 권한 없이 쓸 수 없어 설정·곡 보관소를 둘 수 없습니다.
- 폴더가 없을 때 기본값으로 만들어 주는 경로는 어떤 배포 방식이든 필요합니다(새 PC, 폴더 삭제, 백업 복원).
- 인스톨러가 주는 것은 바로가기·제거 항목·런타임 확인·기본 맵 동봉 정도입니다. 소수 배포 단계라면 **zip + 첫 실행 생성**이 간단하고 서명 없는 인스톨러의 SmartScreen 경고·UAC도 피합니다.
- 권장 순서: ① 데이터 폴더 결정 로직(저장소 안에서 실행하면 `.local/app-data`, 밖에서 실행하면 `%LOCALAPPDATA%`) → ② 설정·곡 리스트·노트 수정 저장을 그 위에 구현 → ③ 배포가 필요해지면 인스톨러는 **실행 파일 배치만** 담당.
- 안전 규칙 5는 `.local/app-data/`만 승인하고 있으므로 `%LOCALAPPDATA%` 사용은 **규칙에 경로를 추가로 명시**해야 진행할 수 있습니다.

## 4. 콘솔 명령 정리 후보 (2026-10-06, 사용자 결정: 기록만 하고 1.0.0에서는 하지 않음)

"이름만으로는 기능이 확실하지 않은데 기능마저 비슷한" 명령을 검토한 결과와 타협안입니다. 사용자가 1.0.1 이후로 미뤘습니다.

| 명령 | 지금 | 타협안 |
| --- | --- | --- |
| `remove` · `delete` | remove: 수정본만 보관(`restore`로 복구) · delete: 모든 곡 영구 삭제 | `remove` 하나로, 곡 리스트 창의 "곡 제거"와 같게(수정본은 보관, 기본·커스텀은 사본 삭제). `delete`를 없앰. 되돌릴 수 없는 일은 옵션으로 켜지 않는다는 원칙에 따라 영구 삭제 옵션은 두지 않음 |
| `cmd` · `help` | cmd: 묶음별 한 줄 목록 · help: 모든 명령 전체 설명 | `help` 하나로: `help`(`[list]`)는 지금의 cmd, `help all`(`*`)은 전체 설명, `help <cmd>`는 그대로. list/all 원칙과 맞음 |
| `copy` · `paste` | paste는 클립보드에서 붙이는 게 아니라 화면에 다시 찍음 · `copy -paste` = `paste -copy` | `paste`를 `recall`로 바꾸고 `copy -paste`를 없앰(프롬프트 빈칸의 `/paste`도 `/recall`) |
| `song` · `info now` | 완전히 같음 | `info`의 기본 키워드를 `[now]`로 두고 `song`을 없앰, song의 `-id`를 info로 |
| `get` · `property` | property의 "구역의 설정과 값"이 get 여러 번과 같음 | `get [<section>[.<setting>]]` 하나로, 받는 값은 `get -choices <setting>` |
| `checkpoint` · `locate` | 둘 다 시작 위치를 옮김 | 합치면 길어지므로 `locate`를 `tile`로 이름만(영어 화면의 구간 칸 이름이 "Tile") |

그대로 두기를 권한 것: `option -keywords` = `keyword -options`, `id`·`title` ≈ `info -id`·`playlist -id`, 일부러 둔 바로가기 `speed`·`autosave`, 대상이 다른 `restore`·`rollback`.

## 5. 가변 인자를 더 받을 수 있는 키워드 (2026-10-06)

1.0.0에서 가변 인자(쉼표로 여러 개)는 `scannow`·`install`뿐입니다. 쉼표가 값 안에 들어갈 수 없는 곳만 후보이며, 곡 제목은 쉼표가 들어갈 수 있어 `load`·`retitle`은 안 됩니다.

- `hide`·`show`·`remove <id>, …` — 여러 곡을 한 번에
- `info <id>, …`
- `get <setting>, …`
- `help`·`option`·`keyword <cmd>, …`
- `playlist`·`id`·`title <string>, …` — `playlist base, edited`처럼 합집합
- `report done`·`undone`·`erase <title>, …` (메모 제목에는 쉼표가 없음)
