# 일반판 외부 환경 대응

대상은 Windows 일반판 커스텀 맵입니다(DLC 제외). 모든 이벤트·모든 게임 버전의 지원을 뜻하지 않습니다.

## 근거

- [개발사 Steam 공지](https://steamcommunity.com/app/977950/allnews/): 보정 화면·중간 시작 동기화·일시정지 수정, DSP 버퍼 변경 뒤 재보정 안내. 게임 앱 버전만으로 맵 형식이나 지연이 같다고 볼 수 없습니다(변경 내역 근거일 뿐 타이밍 수식 근거가 아님).
- 게임 파일(`Assembly-CSharp.dll`, SHA-256 `0D1524DA…7F40CD`)의 `scrConductor.get_adjustedCountdownTicks`·`get_dspTimeSongPosZero`·`get_calibration_i`·`get_calibration_v`·`Update`를 ReflectionOnly로 확인: 카운트다운·곡 오프셋·오디오 pitch·입력·화면 보정은 서로 다른 값입니다. 다른 빌드와의 동일성은 보장하지 않습니다.
- 우리 배속은 시간 비례 변환이며 게임 오디오 엔진([Unity AudioSource.pitch](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/AudioSource-pitch.html))을 복제하지 않습니다.

## 대응 표

| 요소 | 대응 | 경계 |
| --- | --- | --- |
| 게임 버전 / 맵 형식 버전 | 구분해 형식 번호를 안내 | 검증된 형식만([파서](adofai-parser.md)). 원본 version을 바꿔 우회하지 않음 |
| 시작 전 로딩·카운트다운 | 수동 시작 대기(기본 0ms) | 첫 타격 때 시작하면 0. 로딩 완료 자동 감지 없음(게임 링크 제외) |
| offset / countdownTicks / separateCountdownTime | 읽어서 곡 정보에 표시 | 자동 대기 시간으로 바꾸지 않음 |
| 긴 휴식·느린 BPM·Pause | 타임라인 간격 유지, 다음 노트까지 남은 시간 표시 | Pause 이벤트와 일시정지 버튼은 별개 |
| 배속 | 기본 100%, 1~1000% | 게임 배속을 수동으로 맞춤(게임 링크는 100%에서만). 원문 pitch는 파서가 따로 처리 |
| 게임 메뉴·일시정지 | 앱의 일시정지·이어하기·Esc | 게임 상태를 감지하지 않음(게임 링크로 따라갈 때 제외) |
| 입력·오디오·디스플레이 지연 | 표시 보정(±ms), 판정 보정 노트 수 | 하드웨어·게임 보정을 자동으로 읽지 않음 |
| 키·포커스 | Raw Input 관찰과 전경 필터 | 게임이 키를 막는지는 알 수 없음. 마우스·패드 시작 감지 없음 |
| Workshop 갱신 | 수동 Map Sync | 파일 감시·다운로드 없음. `.adozip` 추출 없음, 음원을 받지 않음 |

## 시간 처리

`r = 배속 / 100`, `D = 시작 대기(ms)`. 체크포인트 첫 hit를 뺀 원본 시각을 `r`로 나눈 뒤 동타·동적 모드를 계산하고, 그 뒤 모든 표시 hit에 `D`를 더합니다. 그래서 동타 간격과 모드 경계는 **실제로 재생되는 간격** 기준이고 시작 대기는 묶음에 영향이 없습니다. 파서·캐시에는 저장하지 않습니다.

체크포인트 진행은 `원본 시작 시각 + max(0, 경과 − D) × r`. 표시 보정은 렌더링에만 적용합니다. 일시정지는 경과 시간을 고정하고 이어하기는 시계 기준점만 조정합니다. Reset마다 대기를 다시 적용하고 이어하기에는 새로 붙이지 않습니다.

예: 원본 상대 시각 `0, 500, 4000ms`, 배속 50%, 대기 1500ms → 표시 `1500, 2500, 9500ms`.

## 게임과 함께 실행할 때 렉 (GPU 배치)

하이브리드 GPU 노트북(내장 GPU가 화면·dwm 합성, 외장 GPU)에서 앱이 게임과 같은 외장 GPU에서 그려지면, 무거운 곡에서 앱의 화면 갱신이 게임 프레임 뒤에서 기다린 뒤 내장 GPU로 복사되어 끊깁니다(앱 자체는 GPU 3D 약 5%). **해결(사용자 확인)**: Windows 설정 → 디스플레이 → 그래픽에서 `Visualizer.App.exe`(Release·Debug 경로 각각)를 **절전(내장 GPU)**으로 지정. 비슷한 제보는 코드 성능보다 먼저 두 프로그램이 같은 GPU를 쓰는지 봅니다. 앱은 게임·Windows 설정을 바꾸지 않습니다.
