# 체크포인트 연동

## 사용

1. **맵 선택**을 펼쳐 **맵 동기화 → 곡 불러오기**, 또는 위쪽 **예제 (Plum - R)**를 누릅니다(예제는 곡 목록에 넣지 않고 바로 불러옵니다). 이전 캐시는 재동기화해야 합니다.
2. 노트 영역 위 목록에서 **처음부터** 또는 **체크포인트 1~6**을 선택합니다.
3. 선택 즉시 해당 구간의 노트를 정지 배치합니다. **시작/J**는 준비된 첫 타격을 t=0으로 재생합니다. 화면이 꺼져 있으면 먼저 **켜기 / 끄기/F8**을 누릅니다.
4. 재생 중 목록은 Visualizer 시계 기준으로 갱신됩니다. 체크포인트 줄 오른쪽의 **자동** 토글로 바로 켜고 끕니다(2026-09-14 오후에 setting의 체크포인트 칸을 없애고 메인 화면으로 되돌림). 끄면 재생 중에도 선택한 체크포인트를 유지하고, 끄고 켜는 것만으로 노트를 다시 준비하지 않습니다. 사용자 안내에 따라 게임은 배속이나 연습 구간에서 체크포인트를 쓰지 않으므로, **배속이 100%가 아니거나 구간에서 시작하면** 설정과 관계없이 자동 진행이 꺼지고, 토글도 꺼진 상태로 잠깁니다(마우스를 올리면 이유 표시). **도달 후 대기 시간**은 setting → 타이밍에 있습니다. 이전/다음 체크포인트 키는 setting → 조작 키에서 바꿀 수 있습니다(기본 ↓/↑). 목록·↑/↓로 직접 고르는 것은 계속 가능합니다. **재설정/Enter**는 현재 선택된 구간을 다시 준비합니다. 게임 사망/체크포인트 선택은 감지하지 않으므로 서로 다른 위치라면 직접 선택합니다.

UI의 `처음부터`는 내부 번호 1, 맵의 첫 체크포인트는 내부 번호 2입니다. 표시는 **체크포인트 1 · 타일 64 → 64**처럼 원본 타일과 재시작 타일을 구분합니다.

## 확인 근거와 지원 경계

2026-09-13 설치된 ADOFAI의 `A Dance of Fire and Ice_Data/Managed/Assembly-CSharp.dll`을 .NET Framework의 ReflectionOnlyLoadFrom으로 **파일에서 읽어** 메서드 IL을 확인했습니다. 게임 코드는 실행하거나 복사하지 않았으며, 실행 중 게임 메모리에는 접근하지 않았습니다. 분석 도구는 프로젝트 내부 `.local/inspect-checkpoint.ps1`에만 생성했습니다.

- 확인한 DLL SHA-256: `0D1524DABF0F8C67AA58BA1992D6ED858522B9094490EBBB00E5E8AEFF7F40CD`.
- `ffxCheckpoint.get_runOnHit`: 타일 타격 시 실행되는 이벤트입니다.
- `ffxCheckpoint.Decode`: tileOffset 기본값 0. `floor + tileOffset`을 0부터 `listFloors.Count - 2`까지 제한합니다. 현재 지원하는 angleData 맵에서는 끝 마커를 포함하여 floor가 0~angleData.Length이므로 상한은 angleData.Length-1입니다.
- `ffxCheckpoint.StartEffect`: 타일 번호와 offset의 합을 재시작 위치로 저장하며, 기존 저장 위치보다 커야 갱신합니다. 일반 플레이를 대상으로 하며 speed trial/practice/특수 판정 모드는 이 Visualizer의 연동 범위가 아닙니다.
- `scnGame.FinishCustomLevelLoading`: 저장된 체크포인트 타일을 현재 위치로 설정합니다. 기존 노트 정의(다음 타일로 이동하는 타격)에 맞춰 재시작 타일 **이후** 첫 hit를 선택합니다.

`TimelineCheckpoint`는 활성화 시각, 원본 floor, 재시작 floor, 재시작 후 첫 hit index를 분리합니다. 양수 offset 때문에 체크포인트 표시가 뒤늦게 바뀌거나, 음수 offset 때문에 선택 직후 이전 체크포인트로 돌아가는 것을 방지합니다. 재시작 때 건너뛴 구간은 실제 통과로 간주하지 않습니다.

시작/종료 타일에 놓인 체크포인트, **중간 회전 타일로의 재시작**, 조건부/angleOffset 체크포인트와 체크포인트를 반복하는 RepeatEvents는 미검증이므로 지원하지 않습니다. **중간 회전 타일 위의 체크포인트 이벤트는 앱 0.2.1부터 허용합니다**(재시작 타일이 일반 타일일 때만, ぴれんどらー - Unstable haze 대응). 근거: `scrPlanet.MoveToNextFloor`가 행성이 올라선 타일의 효과를 실행하며 그 함수 자체가 `scrFloor.midSpin`을 읽고, `scrPlayer.Hit`도 `currFloor.midSpin`으로 `midspinInfiniteMargin`을 정하므로 중간 회전 타일도 현재 타일이 됩니다. 저장되는 재시작 위치는 `ffxCheckpoint.StartEffect`가 쓰는 `floor.seqID + tileOffset`이라 이벤트 타일이 중간 회전인지와 무관합니다. 범위를 벗어나는 offset은 확인한 규칙대로 제한하고, 재시작 위치를 전진시키지 않는 이벤트는 무시합니다.

실제 게임에서 모든 체크포인트를 재생해 동기화 오차까지 대조한 상태는 아닙니다. 자동 진행 표시는 게임 상태 관찰이 아닌 Visualizer의 타임라인 계산입니다. 원문 음악 offset/countdown은 기존 첫 hit 기준 시작 방식에 섞지 않습니다.

## 방향키 및 적용 대기

- **↑**는 다음, **↓**는 이전 체크포인트를 즉시 정지 배치합니다(2026-09-14에 ←/→에서 변경: 좌우 방향키는 ADOFAI의 판정 변경 키와 겹침). 목록 순서로 이동하며 앱 0.0.2부터 처음과 마지막에서 반대쪽 끝으로 순환합니다. 체크포인트가 1개 이하이면 화면의 ◀ ▶는 비활성(회색)입니다. 게임 전경 필터와 편집 중 입력 제외는 Reset/Start와 동일합니다. 길게 누르기는 한 번의 입력으로 처리합니다. 위아래 방향키는 다른 조작 키·레인 키에 중복 지정할 수 없고, 좌우 방향키는 이제 자유롭게 지정할 수 있습니다.
- 노트 이동 시간 기본값은 **720ms**입니다. **자동 적용 시점은 앱 0.1.2에서 바뀌었습니다(사용자 요청):** 체크포인트 타일의 노트를 누르면 그 순간, 누르지 않으면 그 노트의 **입력 인정 범위가 끝날 때**(기본 +150ms) 적용합니다. 이전의 "도달 후 대기 시간(기본 1000ms)" 설정은 실제로 쓰이지 않아 제거했습니다. 표시 시각 기준이므로 동타 정렬·배속·시작 대기·표시 보정을 그대로 반영합니다.
- 실제 체크포인트 이벤트 타일 시각을 기준으로 하며 tileOffset 재시작 타일과 구분합니다. 시작 대기·배속·동타의 표시 시각·표시 보정을 반영합니다. 이동 시간을 바꿔도 이미 정해진 판정선 도달 시각에 이동 시간을 다시 더하지 않습니다. 일시정지 중에는 적용 대기도 멈춥니다.
- 체크포인트 키(앱 0.2.2부터 기본 `-`/`+`, 비워 둘 수 있음)나 목록으로 직접 선택한 체크포인트는 즉시 준비합니다. 위 지연은 재생 중 자동 진행에만 적용하며 원본 맵과 캐시 메타데이터는 바꾸지 않습니다.

## 구간 시작 (게임 연습 모드와 같은 타일 번호)

체크포인트 줄 오른쪽 **구간** 칸에 타일 번호를 넣고 Enter를 누르면, 그 타일부터 정지 배치합니다. 칸을 비우면 체크포인트 기준으로 돌아가고, 체크포인트를 고르거나 ↑/↓로 이동하면 구간 입력은 해제됩니다. 재설정·켜기/끄기·노트 규칙 변경 뒤에도 같은 타일에서 다시 준비합니다. 재생 중 자동 체크포인트 진행은 이 시작 위치보다 앞에 있는 마지막 체크포인트부터 이어집니다.

**노트 배치와 시작 키 (2026-09-14 정정).** 구간은 그 위치에서 패턴을 새로 시작하지 않습니다. 곡 처음부터 재생할 때 만들어지는 노트 배치를 그대로 잘라 쓰므로, 같은 노트는 처음부터 재생할 때와 같은 레인에 내려옵니다. 따라서 첫 노트가 Initial Tile(J 레인)이 아닐 수 있고, 구간을 시작하는 키는 **첫 노트 레인의 키**로 바뀝니다(첫 노트가 동타면 두 레인 키 모두). 이때 시작 키(J)는 시작하지 않으며, 바뀐 키는 상태 메시지와 아래 키 안내에 표시됩니다. 화면의 시작 버튼은 그대로 쓸 수 있습니다. **처음부터**는 이전과 같이 Initial Tile에서 배치하고 J로 시작합니다. **두 번째 이후 체크포인트 시작도 앱 0.0.3부터 같은 방식**입니다: 곡 처음부터 만든 배치를 잘라 쓰고 첫 노트 레인의 키로 시작합니다. 이전에는 체크포인트마다 Initial Tile(5번, J 레인)에서 다시 배치해 어느 체크포인트든 J로 시작했습니다. 곡 앞부분에 배치할 수 없는 동타가 있으면 뒤 체크포인트에서 시작해도 이유를 표시하고 준비를 중단합니다.

2026-09-14 같은 게임 파일(SHA-256 위와 동일)을 ReflectionOnly로 읽어 확인했습니다.
- `scrController.SetPracticeMode`: 연습 모드에 들어갈 때 기존 `GCS.checkpointNum`을 `checkpointBeforePractice`에 보관하고, 계산한 시작 타일 번호를 보정 없이 `GCS.checkpointNum`에 넣습니다. 연습을 끄면 보관한 값을 되돌립니다.
- `PracticeTimeline.Init`/`SetPositions`: 연습 구간 시작 `practiceStart`를 `GCS.checkpointNum`에서 읽고, 사용자가 조정한 값을 보정 없이 다시 `GCS.checkpointNum`에 쓴 뒤 재시작합니다. 시작 타일은 0 이상으로 제한됩니다.

즉 연습 시작 타일은 체크포인트 재시작과 같은 저장 위치로 처리되므로, 위에서 확인한 `scnGame.FinishCustomLevelLoading` 규칙대로 **해당 타일 이후 첫 hit**부터 준비합니다(타일 20 → 첫 타격 타일 21, 중간 회전이면 그다음 타격 타일). 체크포인트와 마찬가지로 중간 회전 타일에서의 시작은 미검증이라 거부하며, 마지막 타일 이후에는 노트가 없어 거부합니다. 연습 구간 끝(`practiceLength`)과 게임의 배속은 적용하지 않으며, 배속은 setting의 배속으로 수동으로 맞춥니다.

타일 번호는 v6 파서(`adofai-v6-practice-tiles`)가 hit마다 캐시에 저장합니다. 맵 동기화가 필요한 이유는 시작 키 규칙이 아니라, 이전 캐시에 hit별 **타일 번호 자체가 없기** 때문입니다(hit 시각만으로는 게임 타일 번호를 알 수 없음). v6 캐시로 한 번 동기화하면 이후 구간 변경·레인 배치·시작 키 변경에는 다시 동기화할 필요가 없습니다. 합성 규칙 미리보기에는 게임 타일이 없어 구간을 쓸 수 없습니다.

## 세로 화면 배치

- 기본 창 크기 480×800 DIP, 최소 400×640. 맵 선택을 접으면 노트 공간이 늘어납니다.
- 아래쪽 **⚙** 버튼으로 별도 `setting` 창을 엽니다. 자세한 상태/오류는 **상태 상세**에서 확인합니다.
- 최대 4키이면 네 레인만 표시합니다. 기본 패턴의 논리 타일 번호 **3, 4, 5, 6**을 그대로 유지합니다. 최대 1/2/8키도 각각 그 수만큼 표시합니다.
- 동적 모드의 하위 패턴은 최대 모드 패턴에 포함된 타일만 사용할 수 있습니다. 숨겨진 레인에 노트가 생성되지 않도록 설정 적용 시 검사합니다. 타일 수 변화에 따라 화면 폭이 흔들리지 않도록 최대 모드의 레인 구성을 유지합니다.
