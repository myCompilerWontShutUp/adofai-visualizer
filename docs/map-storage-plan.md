# 맵 저장 구조 · 맵 수정 계획 (계획, 미구현)

2026-09-20 사용자 설계. **1~3단계는 앱 0.4.1에서 구현했습니다**(저장 폴더 3분할·보관소 제거, 동기화/resync/remove/id, 그룹 필터와 `n*` 표시). **4단계인 수정 화면(8절)도 앱 0.4.2에서 구현했습니다.**
앱 0.3.1~0.3.4의 **보관소는 이 구조로 대체되므로 제거합니다**(아래 6절).

## 1. 목표 구조

```text
스팀 폴더 (읽기 전용)          구독 중인 창작마당 맵. 앱은 절대 쓰지 않음
저장 폴더 (읽기·쓰기)
  기본 맵/                     게임 기본·이벤트 맵 (우선 비워 둠)
  커스텀 맵/                   동기화로 스팀 폴더에서 복사해 온 맵
  수정된 맵/                   기본·커스텀 맵 중 타일을 고친 것
  map-cache/library.json       캐시 = 파싱 결과
  settings.json, songs.json    설정과 곡 리스트 선택
```

- **기본 맵**: 게임에 `.adofai`가 없어 AssetRipper로 추출해 넣습니다(사용자가 이미 성공). 배포는 **개인용**이므로 동봉에 문제가 없습니다. 처음에는 폴더만 만들고 비워 둡니다.
- **커스텀 맵**: 스팀 폴더의 사본. 여기가 앱이 실제로 읽는 곳입니다.
- **수정된 맵**: 원본 사본 + 수정 오버레이(2절).

## 2. 수정된 맵의 형태 (사용자 결정)

**수정할 수 있는 것은 레인 위치와 동타 병합·분리뿐입니다.** 각도·이벤트·타이밍은 건드리지 않습니다.
따라서 **원본 `.adofai` 복사본 + 오버레이 json**을 한 폴더에 두고, `.adofai`는 다시 쓰지 않습니다.

- 레인도 동타 묶음도 `.adofai`에 없는 개념(앱이 타이밍에서 만들어 냄)이라 맵 파일로 표현할 수 없습니다.
- 오버레이가 담는 것: **원본 hit 번호 → 타일**, **묶음 지정**(병합·분해), 원본 해시. 원본 hit 시각은 바꾸지 않습니다.
- 원본을 복사해 두는 이유는 `resync`가 커스텀 맵을 전량 재구축해도 **수정본이 홀로 서게** 하기 위해서입니다.
- 파서를 고쳐도 원본이 있으므로 재파싱·재검증이 됩니다.

## 3. 흐름

| 동작 | 하는 일 |
| --- | --- |
| **동기화** | 스팀 폴더 → 커스텀 맵으로 복사(증분). 그다음 세 폴더를 모두 파싱해 캐시에 넣습니다 |
| **그룹 선택** | 곡 정렬 아래 `기본 맵 / 커스텀 맵 / 수정된 맵 / 전체`. **필터일 뿐** 재파싱하지 않습니다(사용자 결정) |
| **resync** | 커스텀 맵을 스팀 폴더와 **완전히 일치**시킵니다(3-1절). 진행률 표시, `[Y/n]` 확인. 스팀에서 구독 해제한 곡은 여기서 **사라집니다 — 그것이 목적입니다** |
| **remove {id}** | 그 곡을 커스텀 맵이나 수정된 맵에서 제거. 커스텀 맵은 동기화·resync로 되살아납니다 |

### 3-1. resync를 안전하게 하는 방법 (구현자 판단)

지우고 바로 복사하면 중간에 실패했을 때 커스텀 맵이 반쯤 빈 채로 남습니다. 그래서 **새로 만든 뒤 바꿔치기**합니다.

1. `커스텀 맵.new`에 스팀 폴더의 `.adofai`를 복사합니다(진행률은 여기서 나옵니다).
2. 다 끝나면 `커스텀 맵` → `커스텀 맵.old`, `커스텀 맵.new` → `커스텀 맵`으로 이름만 바꿉니다. 같은 드라이브 안이라 거의 즉시이고 중간 상태가 없습니다.
3. 마지막으로 `.old`를 지웁니다.
4. 중간에 실패하거나 취소하면 `.new`만 지우고 **기존 커스텀 맵은 그대로** 둡니다.

**복사 대상은 `.adofai`뿐입니다.** 음악·이미지는 앱이 쓰지 않으므로 옮기지 않습니다. 덕분에 용량이 작아 잠시 두 벌이 있어도 부담이 없고, 복사도 빠릅니다.

## 4. id 체계 (사용자 결정: 표시용으로 추가)

- 내부 식별은 지금처럼 **경로 해시**를 씁니다. 곡 리스트 선택과 수정본 연결이 그대로 유지됩니다.
- 그 위에 **8자리 표시용 id**를 장부 파일에 짝지어 둡니다. 첫 자리는 종류입니다: `0` 기본 맵 · `1` 커스텀 맵 · `2` 수정된 맵.
- 난수로 만들되 이미 쓰인 값과 겹치지 않게 검사합니다. 콘솔 `id`와 `remove {id}`가 이 값을 씁니다.
- 수정본은 **자기 id와 원본 id를 함께** 들고 있어야 원본이 갱신됐을 때 알릴 수 있습니다.

## 5. 화면

- 곡 리스트 섹션의 버튼을 셋으로: **곡 상세설정(1/2) · 현재 곡 수정(1/4) · 재동기화(1/4)**.
  - 재동기화는 초기화처럼 빨간 버튼이고 확인 창을 한 번 더 거칩니다.
  - 현재 곡 수정은 닫기 전에 변경이 있으면 "수정된 항목이 있습니다" 경고를 띄우고, 창이 이미 있으면 재사용합니다.
- 수정된 맵은 목록에서 이름 앞에 **슬롯 번호와 `*`**를 붙입니다(예: 2번 슬롯이면 `2*Plum - R`). 표시 이름을 바꾼 곡도 같은 규칙입니다.
- 그라데이션 버튼 규칙(변경이 있을 때만 강조)은 기존과 같습니다.

## 6. 보관소 제거

0.3.1~0.3.4의 보관 기능(수동 보관·보관 해제 버튼, 원문 해시 중복 제거, 동기화 2패스, "보관됨" 표시)은 커스텀 맵이 대신하므로 **제거**합니다.
다음 세 가지는 커스텀 맵·수정된 맵 폴더 관리로 **이름만 바꿔 재사용**합니다.

- 저장 폴더 밖·맵 폴더·reparse point로 새지 않는지 검사하는 쓰기 경계
- 서로 다른 곡이 같은 폴더·파일 이름일 때 이름 비켜쓰기(앱 0.3.2)
- 라이브러리 폴더 안에서만 지우는 삭제 경계 → `remove`, `resync`가 씁니다

## 7. 콘솔 명령 (추가 예정)

| 명령 | 하는 일 |
| --- | --- |
| `id` | 곡들의 8자리 id를 보여줍니다 |
| `resync` | 커스텀 맵을 스팀 폴더와 일치시킵니다(전량 재구축, 진행률, `[Y/n]`) |
| `remove {id}` | 그 곡을 커스텀 맵·수정된 맵에서 제거합니다 |
| `edit` | 현재 곡 수정을 시작합니다. 설정 창이 열려 있으면 닫습니다(변경이 있으면 경고, 창은 재사용) |

## 8. 수정 화면 (구현은 나중)

**고칠 수 있는 것은 레인 위치와 동타 병합·분리뿐입니다.**

1. 인게임 트랙을 그대로 씁니다.
2. 곡 선택 등 불필요한 부분을 없애고 **체크포인트와 노트 이동만** 남깁니다(체크포인트 "자동"은 없앰).
3. 상세 정보 표시는 남깁니다.
4. 곡을 위아래로 훑는 **스크롤**을 넣고, 스크롤은 확실히 보이게 합니다.
5. 모든 노트 위에 **원본 hit 번호**를 작게 표시합니다. 동타는 `44-45`처럼 `-`로 잇습니다.
6. 디자인은 기존 설정값을 따릅니다.
7. 위쪽에 저장·취소. 변경이 있을 때 취소하면 경고합니다.

### 8-1. 조작 (2026-09-20 확정)

- **고르기**: 클릭, 드래그 박스, `Ctrl+클릭`(하나씩), `Shift+클릭`(범위), `Ctrl+A`, `Esc`/빈 곳 클릭으로 해제. 롱노트는 시작·끝 중 하나만 눌러도 둘 다 잡힙니다.
- **노트 이동**: `w` 다음 노트, `s` 이전 노트. 화면이 따라가되 **너무 위나 아래에 붙지 않게** 여유를 두고 스크롤합니다.
- **레인 조정**: `a` / `d`로 한 칸씩. 여러 개를 골랐을 때 **한쪽이 벽에 닿으면 전체가 멈춥니다**.
- **숫자 `1`~`8`**: 고른 것들을 **통째로 상대 이동**합니다. 누른 번호가 선택 범위보다 오른쪽이면 최대 레인이 그 번호가 되도록, 왼쪽이면 최소 레인이 그 번호가 되도록 밉니다. 번호가 이미 선택 범위 안이면 움직이지 않습니다(예: 4키에서 1·2를 잡고 `3` → 2-3, `4` → 3-4, 1~4를 모두 잡으면 아무 동작 없음).
- **병합** `m`: 고른 2개를 한 동타로. **간격 40ms까지** 허용합니다. **동타 인접 규칙(가운데 쌍 금지 등)은 수동 편집에서 적용하지 않습니다.**
- **분해** `u`: 동타를 낱개로 되돌립니다.
- **되돌리기** `Ctrl+Z`, **다시 하기** `Ctrl+Shift+Z`.
- **확대·축소**: `Ctrl+휠`로 노트 속도를 바꿔 더 촘촘하게/성기게 봅니다. 표시만 바뀌고 저장되는 값은 그대로입니다. 보이는 구간만 그리고 브러시를 Freeze해 렉이 없게 만듭니다.
- **재생은 없습니다.** 노트 추가·삭제도 없습니다.

### 8-1-1. 옮길 수 없을 때

모달 창은 띄우지 않습니다.

| 경우 | 처리 |
| --- | --- |
| 벽에 닿음 · 보이는 타일 밖 | 조용히 무시 |
| 같은 시각에 그 레인을 쓰는 노트가 있음 | 하단 한 줄 |
| 롱노트가 그 레인을 물고 있음 | 하단 한 줄 |
| 병합 간격 40ms 초과, 또는 2개가 아님 | 하단 한 줄 |

### 8-2. 슬롯

- 한 곡당 **최대 9개**까지 수정본을 만듭니다. 목록에는 **항상 슬롯 번호**가 붙습니다(첫 슬롯도 `1*Plum - R`).
- 저장할 때 **어느 슬롯에 넣을지 고르거나 기존 슬롯을 덮어씁니다.**
- 수정은 **시작할 당시의 설정을 기준**으로 만들어집니다. 슬롯에는 **노트 규칙 설정만** 저장합니다(최대·최소 타일 수, 패턴과 순서, 경계값, 동타 간격, 감소 전환처럼 `HasSameNoteRulesAs`가 보는 값). 색·두께·이동 시간 같은 보기 설정은 언제나 **현재 값**을 따르므로, 나중에 디자인을 바꿔도 수정본만 옛 모습으로 남지 않습니다.

## 9. 열린 질문 없음 (2026-09-20 모두 확정)

- 구독 해제한 곡은 `resync`에서 사라집니다(그것이 목적).
- `resync`는 새 폴더에 만든 뒤 교체하며 `.adofai`만 복사합니다(구현자 판단).
- 노트 위 숫자는 원본 hit 번호, 동타는 `44-45`.
- 병합은 동타 판정 간격 안에서만, 되돌리기 `Ctrl+Z`/`Ctrl+Y`, 슬롯은 첫 번째도 번호를 적고, 슬롯에는 노트 규칙 설정만 저장합니다.

구현 지시가 오면 이 문서대로 시작합니다. 순서 제안: ① 저장 폴더 3분할과 보관소 제거 → ② 동기화·`resync`·`remove`·`id` → ③ 그룹 필터와 `n*` 표시 → ④ 수정 화면.
