# report 편집기 기획서 (0.9.1 작성, **구현됨**)

콘솔의 `report` 명령을 **vim처럼 터미널 안에서 열리는 편집기**로 다시 만드는 계획입니다. 0.9.1에 들어간 줄 단위 방식은 사용자가 원한 것과 어긋나서, 아래 내용을 확인받은 뒤 갈아엎습니다.

## 1. 지금 무엇이 어긋났나

0.9.1의 `report`는 **콘솔 입력줄을 그대로 쓰는 줄 단위 편집**입니다.

- `i`를 치면 "쓰기 모드"가 되지만, **한 줄을 치고 Enter를 누를 때마다 그 줄이 메모에 추가**됩니다. Enter가 줄바꿈이 아니라 "제출"입니다.
- 화면은 여전히 콘솔 기록이고, 메모의 내용은 열 때 한 번 찍어 줄 뿐입니다. **지금 쓰고 있는 글이 어떻게 생겼는지 보이지 않습니다.**
- 커서를 위로 올려 가운데 줄을 고칠 수 없습니다. 고치려면 `:delete` 후 다시 쓰는 수밖에 없습니다.

사용자가 원한 것은 **편집기 화면**입니다: 터미널 위에 메모장 같은 층이 뜨고, `i`는 모드 전환(토글)이며, Enter는 줄바꿈이고, Esc로 모드를 빠져나오고, `:wq`로 저장하며 터미널로 돌아옵니다. 창을 새로 띄우는 것이 아니라 **같은 콘솔 창 안에서 화면만 바뀝니다.**

## 2. 범위

**하는 것**

- 콘솔 창 안의 편집기 층(레이어): 메모 전체가 보이고 커서로 아무 곳이나 고칠 수 있습니다.
- 두 모드(보기 / 쓰기)와 아래 상태줄.
- `:` 명령줄과 `:w` `:q` `:wq` `:q!` `:delete`.
- 저장 위치·형식·버전 청소 규칙은 **지금 그대로**(`<저장소>/reports/<제목>.txt`, 버전의 첫·두 번째 숫자가 바뀌면 전부 삭제).

**하지 않는 것**

- vim의 편집 문법(`dd` `yy` `p` `/검색` `숫자+명령`, 비주얼 모드) — 흉내만 내면 오히려 헷갈립니다.
- 여러 메모를 동시에 열기(탭·분할). 한 번에 하나입니다.
- 실행 취소 스택. WPF 입력칸이 주는 Ctrl+Z를 그대로 씁니다.
- 별도의 창. **콘솔 창 하나를 계속 씁니다.**

## 3. 화면

```
┌────────────────────────────────────────────────────────────┐
│ 1  배속 칸이 사라질 때 LostFocus가 적용으로 처리되던 것     │   ← 메모 본문
│ 2  → 0.9.1에서 고침                                        │     (커서·스크롤 있음)
│ 3                                                          │
│ 4  다음: 설정 검색에 콘솔 이름도 걸리게                     │
│                                                            │
│                                                            │
├────────────────────────────────────────────────────────────┤
│ "speed box"  4 lines  2,14                    -- INSERT -- │   ← 상태줄
└────────────────────────────────────────────────────────────┘
```

- 콘솔 기록은 **가려질 뿐 사라지지 않습니다**. 편집기를 닫으면 치던 자리 그대로 돌아옵니다.
- 글꼴·색은 콘솔과 같습니다(Cascadia Mono, 테마 색).
- 상태줄: 제목, 줄 수, 커서 위치(줄,칸), 오른쪽에 모드. 저장하지 않은 변경이 있으면 제목 뒤에 `[+]`.
- `:`를 누르면 상태줄이 명령줄로 바뀝니다(`:wq` 치는 동안 그대로 보임).

## 4. 모드와 키

| 모드 | 들어가기 | 나가기 | 타자 |
| --- | --- | --- | --- |
| 보기(NORMAL) | 처음 열 때, 쓰기에서 Esc | `:q` `:wq` | 글자가 들어가지 않음 |
| 쓰기(INSERT) | 보기에서 `i` 또는 `o` | Esc | 글자가 커서 자리에 들어감, **Enter는 줄바꿈** |

- 방향키·PageUp/Down·Home/End·마우스 클릭·휠은 **두 모드에서 모두** 커서를 옮깁니다.
- 보기 모드의 키는 `i`(그 자리에서 쓰기), `o`(아래에 새 줄을 만들고 쓰기), `:`(명령줄) 셋뿐입니다.
- Tab은 포커스를 옮기지 않고 **공백 네 칸**을 넣습니다.
- **Ctrl+T는 그대로** 콘솔을 최소화합니다(편집 중에도).
- 한글 입력(IME)을 켭니다. 콘솔 입력줄은 IME를 꺼 두지만 메모는 한국어로 씁니다.

## 5. 명령줄

| 명령 | 하는 일 |
| --- | --- |
| `:w` `:write` | 저장하고 편집기에 남음 |
| `:wq` | 저장하고 터미널로 |
| `:q` `:quit` | 터미널로. 저장하지 않은 변경이 있으면 상태줄에서 `Leave without writing? [Y/n]`로 한 번 물음 |
| `:q!` | 묻지 않고 버리고 나감 |
| `:delete` | 이 메모를 지움(한 번 묻고, 지운 뒤 터미널로) |

- 없는 명령은 상태줄에 `Not an editor command: :xy`로 알리고 보기 모드로 돌아옵니다.
- 명령줄에서 Esc는 명령을 지우고 보기 모드로 돌아옵니다.

## 6. 코드 구조

**새로 만드는 것** — `src/Visualizer.App/Views/ReportEditor.cs`

- `TextBox`(여러 줄·스크롤) + 상태줄 `TextBlock`을 담은 컨트롤. 보기 모드에서는 `IsReadOnly`로 타자를 막고 커서는 보이게 둡니다(`IsReadOnlyCaretVisible`).
- 공개 면: `Title`, `Lines`, `Changed`, `Insert`, `bool Press(Key, ModifierKeys)`(테스트가 키를 직접 넣는 곳), 그리고 콜백 `Save`·`Delete`·`Leave`.
- 파일은 **직접 건드리지 않습니다.** 저장·삭제는 콜백으로 나가고, 그 끝은 지금과 같은 `ICmdHost.WriteReport`/`DeleteReport`입니다.

**고치는 것** — `CmdWindow`

- 창 내용을 `Grid` 두 층으로: 지금의 기록 `TextBox`와 편집기. 열면 편집기만 보이고 포커스도 그쪽입니다.
- `CmdSession.ReportRequested`(새 이벤트, `ExitRequested`와 같은 모양)를 받아 편집기를 띄웁니다.

**덜어내는 것** — `CmdSession`

- `Report` 레코드, `WriteReport`, `EscapeWriting`, `IsWriting`, `ReportPrompt`와 `Submit`의 report 분기를 **모두 지웁니다**(약 120줄). 세션은 다시 "명령을 받는 곳"만 합니다.
- `report <title>` 명령(0.9.2부터 `report write <title>`·`report create <title>`)은 제목을 검사하고 내용을 읽은 뒤 이벤트를 올리는 것까지만 합니다. `report`(인자 없음)의 제목 목록은 그대로입니다.
- `CmdWindow`의 Escape 분기도 원래대로 돌아갑니다(줄 비우기).

**그대로 두는 것** — `ReportBook`(저장·버전 청소), `ICmdHost`의 네 메서드, `docs/console.md`의 저장 규칙.

## 7. 정해진 것 넷 (사용자 결정, 0.9.1)

1. **`:q`의 확인** — 상태줄에서 `[Y/n]`으로 묻습니다. `:q!`도 받습니다(묻지 않고 버림).
2. **줄 번호** — 두지 않습니다. 상태줄의 `줄,칸`으로 충분합니다.
3. **콘솔 창을 닫을 때** — 쓰던 메모를 그대로 기억했다가 콘솔을 다시 열면 **그 상태로 돌아옵니다**. 다만 **앱을 닫을 때**는 돌아올 곳이 없으므로 저장하지 않은 메모가 있으면 경고 창을 띄웁니다.
4. **보기 모드 키** — **`i` 하나뿐**입니다(`o`도 두지 않음).

## 8. 테스트

편집기는 화면이지만 키 처리는 전부 `Press`를 거치므로 하네스에서 그대로 확인할 수 있습니다(수정 창 `NoteEditWindow.Press`와 같은 방식).

- 열면 보기 모드, `i`로 쓰기, Esc로 보기, 상태줄 문구.
- Enter가 **줄을 늘리는지**(제출이 아닌지), 가운데 줄을 고칠 수 있는지.
- `:w`로 저장 호출, `:wq`로 저장 후 나감, `:q`가 변경이 있을 때 묻는지, `:q!`가 버리는지, `:delete`가 지우는지.
- 없는 `:명령`이 상태줄에 남고 모드가 보기로 돌아오는지.
- 콘솔 기록이 편집 중에도 그대로 남아 있다가 돌아오는지.

## 9. 순서와 규모

1. `ReportEditor` 컨트롤(모드·상태줄·명령줄) — 약 250줄
2. `CmdWindow` 두 층 + 이벤트 연결 — 약 40줄
3. `CmdSession`에서 줄 단위 방식 제거 — 약 -120줄
4. 테스트 한 묶음, `docs/console.md`의 report 절 교체

`report`의 **저장 형식과 버전 청소 규칙은 바뀌지 않으므로**, 0.9.1에서 쓴 메모가 있어도 그대로 열립니다.
