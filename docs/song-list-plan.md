# 곡 리스트 · 설정

2026-09-17 계획, **2026-09-18 앱 0.2.8에서 1단계(UI와 저장)를 구현했습니다.** 아래 1~4절은 그때의 요구사항 기록이고,
실제로 만들어진 내용과 결정은 7절에 정리했습니다. 보관소(맵 원문 복사·기본 맵 동봉)는 아직 만들지 않았습니다.

## 1. 요구사항 (사용자 원문 정리)

setting → **일반 설정 아래에 "곡 리스트 · 설정" 섹션**을 추가합니다. 다른 설정과 같이 **적용 버튼을 눌렀을 때** 반영합니다.
이 섹션에서 각 곡에 대한 정보를 볼 수 있어야 합니다.

| 항목 | 형태 | 요구 |
| --- | --- | --- |
| 검색 기능 | 토글 | 기본 활성화. 비활성화하면 검색 없이 목록(리스트업)으로만 고릅니다 |
| 곡 정렬 | 목록 2개 | ① 기준: 난이도 · 생성 날짜 · 이름 · 직접 정렬 등 **존재하는 메타데이터 한정**(파일 정보를 조회할 수 있어야 함) ② 방향: 오름차순 · 내림차순 |
| 곡 리스트 상세보기 | 버튼 | 설정 창 **위에 뜨는 별도 창**을 엽니다 |

- 정렬 기본값은 **현재 지정된 값**이며, 없으면 **난이도**(높은 난이도가 위로).
- 같은 난이도의 정렬 순서는 **구현자가 설계해 결과를 보고**합니다 → 아래 2절 참조.
- 기준을 **직접 정렬**로 두면 오름차순/내림차순 목록은 **비활성화**합니다.
- 직접 정렬 값이 아직 없으면 **마지막으로 적용된 정렬**을 기본으로 씁니다(직접 정렬 후 변동이 있으면 그 순서를 고정, 변동이 없으면 다시 마지막 적용 정렬이 기본).
- **상세보기 창**
  - 터미널 창처럼 별도 창이지만 **설정 창 위에 올라온 창**입니다. 열려 있는 동안 **설정 창이 포커스되면 안 됩니다**(= 설정 창을 소유자로 하는 모달).
  - 적용된 정렬(또는 기존에 직접 정렬한 값) 순서로 곡을 나열합니다.
  - 곡마다 **보이기/숨기기(디자인이 서로 달라야 함) → 이름 변경 → 드래그앤드롭 UI 버튼** 순서로 버튼을 둡니다.
  - 버튼은 **앞으로 더 늘어나고 복잡해질 수 있습니다**(참고 사항, 지금 만들지는 않음).
  - **드래그앤드롭 버튼을 제외한 나머지 버튼의 폭은 같아야** 합니다.
- **곡 리스트 상세보기 내용은 설정 JSON 내보내기에서 제외**합니다(사람마다 곡이 다르므로).

## 2. 이쪽에서 정한 것 (보고)

- **같은 난이도의 순서:** ① 곡 이름(대소문자·문장부호 무시, 한국어 로캘 비교) ② 그래도 같으면 상대 경로. 곡 이름은 화면에 보이는 값이라 눈으로 확인하기 쉽고, 상대 경로는 곡마다 반드시 다르므로 순서가 실행할 때마다 흔들리지 않습니다.
- **값이 없는 곡**(난이도 없음 등)은 방향과 관계없이 **항상 목록 끝**에 두고, 그 안에서는 위 규칙을 씁니다. 그래야 "정보 없음"이 위로 몰리지 않습니다.
- 정렬은 **표시 순서만** 바꿉니다. 노트·타이밍·캐시 내용은 그대로이며, 곡 ◀ ▶ 이동도 같은 순서를 따릅니다.

## 3. 현재 코드에서 알아 둘 것

- 캐시(`.local/app-data/map-cache/library.json`)에 곡마다 있는 값: 곡 이름, 상대 경로, 원문 hash, 파서 버전, 상태, 경고, hit 시각·타일, 체크포인트, `Info`(작곡가·곡명·제작자·난이도). **파일 생성 날짜는 없습니다** → 맵 폴더에서 읽기 전용으로 조회해야 합니다(안전 규칙 3·5는 읽기만 허용하므로 가능).
- 설정은 디스크에 쓰지 않습니다(안전 규칙 7). 승인된 쓰기 위치는 `.local/app-data/`뿐입니다 → 숨김·이름 변경·직접 정렬을 **다음 실행에도 유지하려면 별도 저장 위치 승인이 필요**합니다(질문 3).
- 곡 목록 UI는 `MainViewModel.Songs`(`Library`/`LibraryView`/`SongQuery`/`MoveSong`)와 `MainWindow.xaml`의 `SongPicker`(`SearchComboBox` 스타일)입니다. 검색 토글은 이 스타일 교체로 처리할 수 있습니다.
- 설정 섹션은 `SettingsPanel.xaml.cs` 생성자에서 `AddSection`·`AddField`로 만들고, 새 설정은 `VisualizerSettings` + `DefaultSettings.jsonc` + 두 언어 파일(`Hint.<설정이름>` 포함)에 함께 추가합니다.
- JSON 내보내기 제외는 `SettingsJson`에서 해당 항목을 빼는 방식이 됩니다(가져오기에서도 알 수 없는 항목으로 거부되지 않게 처리 필요).

## 4. 사용자 확정 사항 (2026-09-17 답변)

1. **정렬 기준은 전부 넣습니다**(난이도 · 곡 이름 · 작곡가 · 제작자 · 노트 수 · 곡 길이 · 파일 생성 날짜 · 파일 수정 날짜 · 동기화 순서 · 직접 정렬).
   - 작곡가 정렬의 뜻: **작곡가 이름을 가나다·알파벳 순으로 줄 세우고**, 같은 작곡가의 곡끼리는 2절의 동률 규칙(곡 이름 → 상대 경로)을 씁니다. 즉 "작곡가별로 묶여 보이는" 정렬입니다(아래 질문 1에서 묶음 안 순서를 확인).
2. **"높은 난이도가 위"**가 기본입니다. 난이도에서 방향 표기와 실제 순서가 어긋나지 않도록 아래 질문 2에서 표기를 확인합니다.
3. **저장 승인.** 추후 인스톨러로 배포하므로 앱 전용 저장소를 씁니다. 곡 정보뿐 아니라 **미리 파싱한 곡을 보관하는 저장소**로도 쓰며, 기본 맵도 이곳에 넣을 예정입니다(현재는 Steam 맵 폴더에서 읽어 오기만 함).
4. **숨김은 메인 목록에서만** 빠집니다. 상세보기에는 계속 보이고, **맵 동기화 후에도 유지**합니다(경로 기준).
5. **이름 변경은 표시 이름만** 바꾸고 원본은 유지합니다. 사용자 제안: 같은 버튼을 **빠르게 더블클릭하면 원래 이름으로 초기화**(누르고 이름을 바꾸지 않은 채 다시 누르는 형태). 별도 초기화 버튼은 두지 않습니다.
6. **적용 시점:** 상세 창에서 확정한 뒤 **설정 창의 적용까지 눌러야 최종 반영**합니다. 헷갈리지 않도록 상세 창의 버튼 이름은 **"확인"**으로 두고, 버튼 색이 바뀌는 방식(변경이 있을 때만 강조)은 설정 창과 같게 합니다.
7. **검색 비활성화 시** 곡 칸은 입력이 안 되는 일반 목록으로 바꿉니다(목록을 누를 때 곡 제목이 같이 눌려 불편하다는 의견).
8. **직접 정렬은 상세 창에서만** 합니다. 정렬 기준이 난이도 등이었더라도 **상세 창에서 순서를 바꾸면 자동으로 "직접 정렬"로 바뀌고 오름/내림차순 목록은 비활성화**됩니다.

## 5. 이름 초기화에 대한 제안 (택일 필요)

더블클릭은 빠르기 판정이 필요하고 잘못 눌리기 쉽습니다. 대안으로 **이름 변경 칸을 비운 채 확인하면 원래 이름으로 돌아가는** 방식을 제안합니다(칸 옆에 원본 이름을 흐리게 함께 표시). 버튼은 그대로 하나이고, 빠르기 판정이 없어 실수로 초기화되지 않습니다. 사용자의 더블클릭 안과 함께 질문 3에서 고릅니다.

## 6. 열린 질문 (다음 지시 때 확인)

1. **작곡가·제작자 정렬의 묶음 안 순서**: 같은 작곡가의 곡을 곡 이름순으로 둘까요, 아니면 난이도순(높은 난이도가 위)으로 둘까요?
2. **방향 표기**: 난이도에서 "높은 난이도가 위"가 기본인데, 목록에는 이 상태를 **오름차순**으로 적을까요 **내림차순**으로 적을까요? (다른 기준은 작은 값·이른 날짜가 위 = 오름차순으로 통일할 예정입니다.)
3. **이름 초기화 방식**: 더블클릭(사용자 안)과 빈 칸 확인(5절 제안) 중 무엇으로 할까요?
4. **보관소 범위**: 앱 전용 저장소에 **파싱 결과만** 둘까요, 아니면 `.adofai` 원문까지 복사해 둘까요? 원문을 복사하면 Steam 폴더 없이도 재파싱·재검증이 가능하지만 용량이 늘고, 원본 맵의 복사본을 갖게 됩니다(읽기 전용 규칙은 원본을 건드리지 않으므로 유지됩니다).
5. **보관소 위치**: 지금은 `.local/app-data/`만 승인돼 있습니다. 인스톨러 배포 시에는 어디에 둘까요(설치 폴더 안 / `%LOCALAPPDATA%` / 사용자가 지정)? 지금 단계에서는 `.local/app-data/library/`로 두고 나중에 경로만 바꾸면 될까요?
6. **기본 맵**: 어떤 곡을 기본으로 넣을 계획인가요(출처·배포 허가 확인 필요). 지금은 `.example`의 Plum - R만 읽기 전용 예제로 쓰고 있습니다.
7. **보관소와 맵 폴더의 관계**: 동기화할 때 Steam 폴더에서 읽어 **보관소로 가져오는(import)** 흐름인가요, 아니면 두 곳을 각각 목록에 보여 주나요? 같은 곡이 양쪽에 있으면 어느 쪽을 우선할까요?
8. **"동기화 순서" 정렬**: 캐시에 들어온 순서(가장 최근에 동기화한 곡이 위)로 보면 될까요?
9. **날짜 기준**: 파일 생성·수정 날짜는 맵 폴더의 원본 기준인가요, 보관소로 가져온 시각 기준인가요?
10. **불러온 곡을 숨기면**: 이미 불러와 재생 중인 곡을 숨기면 그대로 두고 목록에서만 빼면 될까요?
11. **상세 창 크기·정보**: 곡마다 이름 외에 무엇을 함께 보여줄까요(난이도·작곡가·노트 수·길이 등)? 지금 캐시에 있는 값은 모두 표시할 수 있습니다.

## 7. 구현된 것 (앱 0.2.8, 2026-09-18)

- **설정**: `SongSearch`(기본 활성화) · `SongSortKey`(기본 `Difficulty`) · `SongSortHighFirst`(기본 참 = 높은 값이 위).
- **정렬 기준 10가지**(`Core/Settings/SongSortField`): 난이도 · 곡 이름 · 작곡가 · 제작자 · 노트 수 · 곡 길이 · 생성 날짜 · 수정 날짜 · 동기화 순서 · 직접 정렬. 값이 없는 곡은 항상 끝, 동률은 곡 이름 → 상대 경로.
- **방향 표기**: "높은 값이 위 / 낮은 값이 위"(사용자 결정). 직접 정렬을 고르면 방향 목록이 잠기고 값은 유지됩니다.
- **상세 창**(`App/Views/SongListWindow`): 설정 창을 소유자로 하는 모달. 곡마다 숨기기·이름 변경(폭 동일) + ≡ 드래그. 정보 줄에 난이도·작곡가·노트 수·길이·체크포인트 수(또는 상태)·수정 날짜·상대 경로. 확인은 변경이 있을 때만 강조.
- **이름 초기화**: 이름 칸을 비우고 확인하면 원래 이름으로 돌아갑니다(사용자 결정). 원래 이름은 칸 아래 안내와 목록의 "원래 이름:" 줄에 보입니다.
- **저장**: 저장소의 `songs.json`(곡 id = 맵 경로 해시)에 숨김·표시 이름·직접 순서만 저장하며, 선택이 하나도 없는 곡은 기록하지 않습니다. 설정 JSON 내보내기에는 들어가지 않습니다.
- **적용 시점**: 상세 창 확인 → 설정 창 적용까지 눌러야 저장됩니다.
- **검색 비활성화**: 곡 칸이 읽기 전용이 되고, 칸을 눌러도 제목이 선택되지 않고 목록이 열립니다.
- **표시 이름 범위**: 메인 목록·◀ ▶·곡 정보 등 화면 전부. 정렬도 표시 이름을 기준으로 합니다. 캐시와 맵 파일은 그대로입니다.

## 9. 한 폴더의 여러 레벨 파일 (앱 0.3.3)

사용자 맵 폴더를 읽어 확인한 실제 사례는 세 가지입니다.

| 사례 | 예 | 처리 |
| --- | --- | --- |
| 에디터 자동 저장 | `backup.adofai` + `main.adofai` | 전처럼 **목록에서 제외**(`IsShadowedEditorBackup`) |
| main 옆의 변형·옛 파일 | `main.adofai` + `sub1.adofai` / `level.adofai` / `low effect.adofai` | **기본 숨김**(`IsBesideMainLevel`). 상세 창에 이유를 적고, "보이기"를 누르면 그 선택이 저장됨 |
| 한 폴더의 독립된 곡 여러 개 | `5-X….adofai` + `6-X….adofai` (main 없음) | **모두 표시** |

근거: 게임의 곡 선택 화면(`scnCLS.DisplayLevel`)이 재생하는 것은 `main.adofai`입니다. 따라서 그 옆의 파일은 그 폴더의 곡이 아니지만, 연습용으로 쓰고 싶을 수 있어 지우지 않고 숨김으로 둡니다.
`SongPreference.Hidden`을 `bool?`로 바꿔 **null = 정하지 않음(자동 규칙 적용)**, true/false = 사용자가 정함으로 구분합니다.

## 8. 보관소 (앱 0.3.1, 2026-09-19) — **존치 여부 미결**

> 2026-09-20: 보관소의 실익이 지금은 적다는 사용자 지적이 있었습니다. 선택지는 ① 그대로 유지 ② "맵 폴더 여러 개 지정"으로 대체하고 보관소 제거 ③ 그냥 제거이며, **사용자가 추후 한 번에 지시**하기로 했습니다. 그때까지 아래 구현은 유지합니다.

사용자 결정으로 열린 질문 4·6·7이 정해졌습니다.

- **보관 범위(4번)**: `.adofai` **원문까지 복사**합니다. 맵 폴더가 없어도 완결되고, 파서를 고치면 보관한 곡을 다시 검증할 수 있습니다.
- **맵 폴더와의 관계(7번)**: **곡마다 수동 보관**입니다. 상세 창의 "보관" 버튼으로 고른 곡만 `<저장소>/library/<맵 폴더 이름>/<파일 이름>`에 복사합니다. 같은 원문 해시가 양쪽에 있으면 **보관본만** 목록에 남고, 보관본에는 "보관됨" 표시가 붙습니다.
- **이름 충돌**: 같은 경로에 다른 내용의 파일이 있으면 `main-<원문 해시 8자>.adofai`처럼 비켜 씁니다. 같은 내용이면 있던 파일을 재사용합니다(앱 0.3.2).
- **보관 해제**: 확인 창을 거쳐 **복사본만** 지웁니다. 원본 맵 파일은 어떤 경우에도 건드리지 않습니다.
- **기본 맵(6번)**: 이번에는 넣지 않습니다. 동봉할 곡과 재배포 허가는 인스톨러를 만들 때 정합니다.
- **적용 시점**: 보관·해제는 파일 작업이라 **즉시** 반영됩니다(숨김·이름·순서·표시 항목은 확인 → 적용까지 눌러야 저장).
- **동기화**: Map Sync가 맵 폴더와 보관소를 **각각** 훑습니다(0.3.4부터 서로 독립). 파서 버전이 오르면 보관한 곡이 자동으로 재검증되고, 맵 폴더가 없어도 보관소만으로 동기화됩니다.
- **저장 폴더에 직접 넣기**: `<저장 폴더>/library/<폴더 이름>/<파일>.adofai`로 직접 복사해 두고 동기화해도 곡으로 올라옵니다. 스팀 폴더가 전혀 없어도 됩니다(음악 파일은 쓰지 않으므로 `.adofai`만 있으면 됩니다). `backup.adofai` 제외와 `main.adofai` 옆 파일 기본 숨김 규칙은 여기에도 똑같이 적용됩니다.

남은 질문은 없습니다. 5번(위치)은 앱 0.2.7의 저장소 규칙, 9번(날짜)은 맵 원본 기준으로 정해졌습니다.
